# PLAN_next-security-upgrade — nextjs-shared

## Title
Upgrade next 16.2.9 → 16.3.6 and remove the postcss 8.5.10 override (security audit fix)

## Plan
A `#reinstall` in chess reported 4 vulnerabilities (1 critical, 2 high, 1 moderate), all coming
from versions pinned in nextjs-shared and copied to every consuming project by Sync All:
next 16.2.9 (critical, 11 advisories incl. RCE), postcss 8.5.10 forced by the `overrides` block
(high, sourceMappingURL file read, fixed above 8.5.22), sharp via next (high), and
@tailwindcss/postcss 4.3.3 (moderate, via postcss only).

Findings and decisions (agreed in chat 2026-09-28):
- The `postcss` override was added 2026-06-15 (3812e55 as `>=8.5.10`, then eb95575 as exact
  `8.5.10`). Most likely it was a security floor lifting next 16.2.9's exact nested `postcss
  8.4.31`. next 16.3.6 pins its own `postcss 8.5.23` (fixed), so the override is obsolete, and it
  was also forcing `@tailwindcss/postcss` (needs `^8.5.16`) below its supported range → removed,
  not raised.
- next 16.3.6 is npm `latest` → synced with no Versions-tab target, so future patches still flow
  through Sync All.
- Per-row sync only (postcss first, then next) — no full Sync All, to avoid unrelated major/minor
  bumps (typescript 7, @types/node 26, dotenv 18, stockfish 19, react 19.3, etc.).
- react/react-dom stay at 19.2.8 (next 16.3.6 accepts `^19`); @tailwindcss/postcss/tailwindcss
  already at latest 4.3.3.
- Accepted side effect: clearing the override target makes Sync All add `postcss` at npm latest
  (8.5.28) to each project's `dependencies`.
- Upgrade executed manually by the user in the Versions tab (`/owner`).
